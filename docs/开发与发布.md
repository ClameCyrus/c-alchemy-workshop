## 安装与更新

唯一对外提供的安装方式为：酒馆扩展面板 → 安装扩展 → 填入仓库地址。

```text
https://github.com/ClameCyrus/c-alchemy-workshop
```

酒馆直接使用main中的manifest及dist。后续在酒馆扩展管理中更新。本项目不创建Release、ZIP或下载附件。

## 本地命令

```text
pnpm install --frozen-lockfile
pnpm run check
pnpm test
pnpm run build
pnpm run check:dist
pnpm run test:ui
```

本地UI检查默认使用已安装的Chrome临时配置，既不连接也不修改当前聊天浏览器。CI使用Playwright Chromium。

```text
pnpm exec playwright install chromium
```

可用`PRW_BROWSER_CHANNEL`选择浏览器。CI功能检查会隔离外部字体请求，真实字体加载另行检查，避免字体CDN影响行为测试结果。

## 工作流如何连接

工作流文件为`.github/workflows/build.yml`。将本地main首次推送到上面的GitHub仓库后，GitHub自动识别该文件并执行，无需额外绑定或个人Token。

1. 安装锁定依赖，检查类型，运行数据和UI测试，完成构建与manifest入口检查。
2. 检查通过后，main的发布任务再次构建，确认远端main仍是已经验证的提交。
3. 仅将dist和第三方许可的变化提交回main，不修改源码、版本号或标签，不强推。
4. PR只检查，不写回；在main页面也可通过Actions的Run workflow手动执行。

检查任务的Token只有读取权限；发布任务通过`permissions: contents: write`请求GitHub自动提供的GITHUB_TOKEN。由该Token生成的推送不会递归触发新的push工作流，另有产物路径过滤。

如果仓库或组织策略阻止工作流写入，需由仓库管理员检查Settings → Actions → General中的Workflow permissions，以及main分支保护是否允许该提交方式；不要在源码中填写个人Token。

本地已有dist，因此首次推送即可提供现有构建。修改后等待Actions的检查与产物更新完成，再通知用户更新。
