# 0.1.2 原生预设拖动检查

日期：2026-11-03，Asia/Hong_Kong。沿独立目录维护并更新到0.1.2，安装入口与README/LICENSE保持原约定。

## 实际环境

只读检查已连接的8600酒馆，未进行用户资源拖放、未刷新或替换运行文件，酒馆助手监听保持关闭。实际列表有329条预设条目、18个工坊组标题；jQuery为3.5.1，jQuery UI为1.13.2。原生Sortable的disabled为false，电脑handle为null，items为`.completion_prompt_manager_prompt_draggable`。工坊锁总开关开启但当前已解锁，旧助手条目锁脚本停用，因此当时不是锁定状态阻止拖动。

原生PromptManager的update回调只按Sortable的toArray更新prompt_order并保存设置，不处理工坊组归属。折叠组标题不属于原生items，没有可以加入该组的原生行落点；工坊在原生停止后仍会按旧归属重排标题。上一轮对正则的跨组处理没有覆盖这条原生预设路径。

## 修复

- 保留原生Sortable实例、items选择器、鼠标/触摸手势机制与正常update保存回调，通过原生sort生命周期补充组归属。没有给预设装另一套PointerEvent拖动或替换条目节点。
- 在原生排序处理mousemove之前记录目标行，防止原生占位符移入目标后遮住真实归属；定位线每帧最多更新一次。直接拖到普通成员前/后进入其组，拖到组标题追加组末尾，拖到无组成员旁退出旧组。
- 从sortstart到原生stop及组归属保存完成一直保持工坊观察器冻结，避免helper样式先清除、后续异步写组时标题又被重插。锁的列表扫描也等待拖动结束。
- 组内排序只执行酒馆原有保存，不额外克隆/提交资源。跨组时在原生排序回调完成后读取新顺序并验证，随后只写组元数据，保持完整raw、原开关、ID、未知字段和排序附加字段不变；按用户原有选择同步第三方组方案，不覆盖未选择同步的版本。
- Escape和列表外松手调用原生cancel。jQuery UI取消时可能先发update再恢复DOM，期间临时抑制该过渡保存，随后恢复原update回调；等原生恢复结束后再解除工坊冻结。
- 不允许在有相关工坊草稿时启动排序；原生控制按钮仍可操作。分组关闭时不处理组归属。元数据保存失败时释放冻结并明确说明原生排序可能已经改变，保留原生有效数据，允许重试。

## 验证与边界

- 39项核心/适配器测试、66项隔离Chrome交互检查、TypeScript、构建和链接安装产物校验通过，无页面运行时异常。
- 新增8项原生排序回归使用真实jQuery 3.5.1和jQuery UI 1.13.2，作为测试开发依赖固定版本，不打包进生产扩展。
- 329条测试中，拖动期间host.load/commit/refresh均没有增加；Sortable实例、原update回调和源行身份不变。跨折叠组、展开组成员前后、退出分组、锁开启后解锁及总开关关闭均成功。原始329项提示词数组逐字保持，原开关与排序附加字段保持。
- 取消不调用原生保存或组提交；模拟组保存失败后可重试；相关草稿阻止排序启动；关闭分组后原生排序仍可用。同组只原生保存，跨组额外提交一次组元数据。
- 结果与截图在忽略目录verification：`native-preset-results.json`、`native-preset-insertion.png`及既有回归文件。实际页只核实环境与源码，未在用户真实预设上执行拖放写入；实体手机及未来第三方拖动引擎变更仍需实际更新后联调。
