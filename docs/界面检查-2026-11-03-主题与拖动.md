## 实际环境与修复

1. 实际主题对所有select使用粉色 `background !important`、`appearance:none !important`、固定padding，并对所有元素使用 `border-radius:0 !important`。工坊加入局部样式保护，恢复下拉箭头，统一36px控件高度和圆角，使用工坊色板变量。正文对比也隔离主题代码块的装饰、阴影和位移，不改变酒馆其他区域。
2. 受保护的系统/占位条目显示“系统”标识与虚线侧边，不显示拖动手柄；保留禁止复制、移动、删除的原有校验。
3. 原生预设编辑、开关节点保持不变，新增“更多”按中心对齐。菜单打开不滚动背景；背景/列表滚动及拖动开始即关闭，菜单内部滚动不关闭。
4. 分组按钮统一为“停用 / 启用”，仍只控制组的执行效果、不改成员原开关。“放弃”与“保存”放在一起，保留确认，保存中不可放弃。
5. 首选侧是对比基准侧：换基准清除旧配对；只换另一侧候选则继续打开对比。关闭正文层保留配对，点原条目可重开。正文上方只列实际不同的设置，包括角色、位置/深度/顺序、触发条件，或正则作用范围、宏替换、裁剪、深度和执行选项。
6. 手机原规则 `.prw-overlay` 优先级低于桌面 `#prw-panel.prw-overlay`，20px桌面边距仍生效，叠加100dvh窗口造成溢出。修复选择器、根节点盒模型和高度上限，标题操作区可换行；320/390px窗口与正文层均贴合视口。
7. 实际原生全局正则有92条，使用jQuery UI sortable，`items:'> *'`、`handle:'.drag-handle'`、delay 50ms。组标题也是列表子节点，原观察器会响应排序占位/行移动并重插标题；原生排序也不会保存工坊组归属。此冲突通过实际DOM、排序配置与源码核对确认，没有在用户数据上执行排序复现。
8. 有工坊分组时采用指针拖放：电脑按住名称、空白或手柄，手机使用手柄；位移超过6px开始。期间暂停分组装饰和观察器刷新，显示前后插入线，支持边缘滚动。松手一次提交顺序和组归属；落到组标题追加组末尾，支持折叠组；落到无组条目则退出原组。Escape/取消不写入。原开关、按钮保留原处理器，拖动后新的点击不会被误拦截。

没有工坊分组或关闭分组功能时继续使用原生排序，不增加“未分组”栏。直接拖放限同一正则范围；跨全局/角色/预设范围继续使用“更多 → 移动到”。未选同步的另一份分组记录保持原样，已选同步方案遵循原写回逻辑。
