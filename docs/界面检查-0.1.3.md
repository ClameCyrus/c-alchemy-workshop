# 0.1.3 大量折叠项拖动卡顿与原生更多按钮

日期：2026-11-04，Asia/Hong_Kong。继续在独立仓库维护，README与LICENSE不变。

## 实际环境和根因

- 实际酒馆0.1.2的index.js SHA256为296f0922c42bd09442dca91d1284c1bac07520bda934efa0ff7ee2254d552c4e，与已发布产物完全相同，不是GitHub只更新了部分文件。
- 连接现有Chrome页，监听保持关闭，锁已解开，原生Sortable仍启用。用户自行触发拖动，记录无刷新性能轨迹。未代用户移动/保存预设，未替换运行插件。
- 此次观测226条原生提示词中147条带工坊折叠隐藏类。性能轨迹显示重复样式计算影响约5380个元素，单次多为40–100ms，最高记录130ms；宽高读取栈落在jQuery尺寸钩子。
- jQuery UI 1.13.2的_mouseStart先执行refreshPositions，再创建helper和触发sortstart。其_refreshItemPositions逐项outerWidth/outerHeight；jQuery 3.5.1对display:none条目尝试临时更改显示再读取尺寸。大量工坊折叠项使整个主题列表反复重算。关闭工坊分组移除隐藏类后，便不会进入这一重复测量路径。
- 0.1.2的观察器冻结在sortstart后才开始，不解决抓起前的尺寸测量；上次329条测试只有2个折叠项，没有覆盖147条隐藏的真实规模。本次不把问题归因于酒馆锁、用户未更新或另一个插件。

## 修复范围

- 仅对当前原生预设Sortable实例的_refreshItemPositions加保护，测量时临时排除工坊的prw-group-folded行，并将其命中几何设为0。
- finally恢复原items数组；不修改options.items、原生toArray、原生update、数据ID或提示词顺序。全部329条仍参与原生保存。普通可见行继续使用原测量函数。
- 分组关闭/视图卸载恢复原方法；实例变化时重新绑定，不覆盖别人之后安装的方法。异常路径也恢复数组。已有组内/跨组/折叠组/取消/锁/草稿保护继续回归。
- 原生更多去掉menu_button类；其自身的尺寸、背景、边框、阴影、位移、SVG和伪元素限定在原生列表内。操作栏不压缩，给图标留4px间距，名称允许收缩换行。不替换原生编辑或开关节点/处理器。
